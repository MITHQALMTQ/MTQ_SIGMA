A binding guard emits SlippageWarning so the frequency of binding guards is itself observable in the transparency layer (§24.4).\nCritical notes — §19.6\n\nFour properties of the entry/exit layer that are frequently misunderstood; each restates a rule already enforced by the code of Listing 11.\n\nMinting does NOT create a 1:1 USD peg\n§19.6.1\n\nMTQ_minted = X_net / P_MTQ,t means the token count delivered for a given deposit moves inversely with the reference price: 1,000 USDC yields ≈ 892.86 MTQ at P = 1.12 but ≈ 1,086.96 MTQ at P = 0.92. This is intentional — the user receives the purchasing-power equivalent of the deposit, not a fixed number of tokens. The mirror image holds at redemption (priced against NAV_t), so a holder never redeems a frozen 1:1 amount either.\n\nPricing doctrine — index in, NAV out\n§19.1\n\nMinting is priced against the adaptive index (invariant I5); redemption is priced against NAV (invariant I6). All operations are atomic, all outputs are slippage-protected, and every price in a quote comes from the canonical multi-source aggregator (Ch 17) rather than any single market feed. Mint and redeem flows are the protocol's natural cash flows — MARP nets them against required weight corrections before any external trade (§10.7, Ch 11).\n\nAtomicity is on-chain only\n§19.6.3\n\n\"Atomic\" refers to on-chain transaction atomicity: the entire mint is one blockchain transaction, and if any step fails the whole transaction reverts with no partial state change. External dependencies — the DEX aggregator, the oracle feeds — may still introduce latency or failure modes of their own (a stale feed, a route that cannot fill within the deadline); the failure mode of every external dependency is a clean revert, never a partially executed mint.\n\nMinimum amounts\n§19.6.4\n\nMIN_MINT and MIN_REDEEM prevent dust transactions that would waste gas and clutter the reserve state; both are 1 MTQ. The blueprint records a discrepancy (governance-adjustable in BP §12.6.4 vs constitutional-immutable in BP §12.7) and resolves it by declaring them compile-time constants — any change requires a governance-approved redeployment.
