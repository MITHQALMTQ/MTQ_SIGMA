## 1. Classification Definitions (per Master Prompt §2, Authority 4)

| Verdict | Meaning |
|---|---|
| **CONFIRMED** | The audit finding is valid. The current code diverges from the Master Blueprint v1.0 in exactly the way the audit describes, and the divergence is not yet remediated. Action required. |
| **CONFIRMED BUT MODIFIED** | The audit finding is valid — the code does diverge from the Master — but the *remediation* the protocol owner has chosen differs from what the audit originally recommended. The finding is closed under a different remediation than the one suggested. |
| **NOT APPLICABLE / SUPERSEDED** | The finding describes an older architecture (the v1.2 pilot or a draft v1.0) that the Master Blueprint v1.0 has already corrected. The current Master does not contain the issue, and the implementation already follows the corrected Master. No action required. |
| **UNPROVEN — REQUIRES DEPLOYED-CODE EVIDENCE** | The finding cannot be confirmed or rejected from source code alone. It requires evidence from the deployed bytecode, an on-chain test, a third-party audit attestation, an independent reproduction of stress results, or a gate-pass certificate per Master §25.5. The source-level claim (e.g., "honest mask = 0x7FF") cannot be downgraded from prose — the protocol owner must produce the deployed-code evidence before the finding is closed. |
| **NEW ISSUE DISCOVERED** | A new issue found during this reconciliation that was not in the original audit corpus. |

### Authority notes

- **Master §22 (BP) — status ladder.** The protocol's status must distinguish five rungs: *specified* → *implemented* → *tested* → *independently audited* → *production authorized*. Source-level inspection can resolve the first two rungs only; the last three require deployment, third-party attestation, and the 11-gate process per Master Listing 15. Findings that turn on the upper three rungs are therefore **UNPROVEN** by construction, not because they are doubtful.
- **Master §25 — reproducibility.** Stress-test results must be reproducible from published seeds, parameter versions, and data versions. Numerical results (e.g., "S5 = 0% survival") cannot be confirmed until independently reproduced with the corrected chain-linked index per Finding 2 of Deliverable A.
- **Master §2.6 Invariant I10 — honest status publication is a hard rule.** The `getHonestStatus()` self-declaration must reflect what is *implemented*, not what is *specified*. Overstating an honest-status bit (e.g., claiming `0x7FF` when only `0x5A7` is truly implemented) is itself a Master violation, independent of the underlying feature gap.
